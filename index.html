01 / Why reformulate

Why the formulation matters

Solve times can vary substantially across formulations of the same optimization problem. A formulation with fewer variables or constraints can reduce the solver’s computational effort, while a formulation with a stronger relaxation can give the solver tighter bounds on the optimal objective value.

To improve solver performance, modeling and optimization experts often exploit problem structure and apply established techniques to reformulate existing models. Such reformulations can yield equivalent formulations that are better suited to optimization solvers.

A reformulation example

Original

∑i=1nxi≤1 y≥xi,∀i xi∈{0,1},i=1,…,n

→

Reformulated

∑i=1nxi≤1 y≥∑i=1nxi xi∈{0,1},i=1,…,n

Fewer constraints
n+1→2

n−1 fewer constraints.

Stronger LP relaxation

For fractional choices, the sum can exceed the largest individual value.

02 / The approach

Why use an LLM for reformulation

LLMs have broad knowledge of mathematical modeling and optimization, including a range of reformulation techniques. They can exploit problem structure to select and apply techniques that can reduce solve time.

Techniques LLM4MOR uses

Presolve
Simplify the formulation before solving to improve solver performance.
Cutting planes
Strengthen the relaxation to help the solver obtain tighter bounds.

The framework can be extended to support more techniques.

03 / The tool

What LLM4MOR does

Give LLM4MOR a model file. It reformulates the model with the aim of reducing solve time. Once the reformulated model passes the checks, you can reuse it to solve instances with data specific to each scenario.

User Guide Source repository ↗

  1. Reformulate the model

    • Generate a syntactically valid reformulated model file.
    • Provide a mapping script to help verify the solution.
    • Provide a report that explains the reformulation.
    ↓

  2. Review and verify

    • Review the model changes described in the reformulation report.
    • Use the mapping script to help verify the solution in the original model.
    ↓

  3. Reuse with new data

    • Keep the reformulated model once all checks pass.
    • Reuse the same reformulated model to solve multiple instances with different data.
04 / Results

How does LLM4MOR affect solve time?

The evaluation compares Gurobi’s solve times before and after reformulation on 575 instances built from model files and data provided with MIPLIB 2017 (Find models.zip ↗). Gurobi uses the same settings for both runs, with a time limit of 3,600 seconds per run.

On hard instances (≥ 1,000 s), the evaluation shows a 6.9× solver speedup after reformulation.
