User guide

Reformulate your first model

Set up LLM4MOR and run the included AMPL example to learn how to reformulate a model, inspect the output, and verify a solution. Then try your own model. For more details, see the GitHub repository.

LLM4MOR currently supports models written in AMPL (.mod) and MiniZinc (.mzn). The framework can be extended to support other mathematical programming languages.

Set up Reformulate

Set up

Clone the repository

With Git installed, run these commands in your terminal.

git clone https://github.com/ZhaoWeiWang0319/LLM4MOR.git
cd LLM4MOR

Software requirements

Install Python 3.9 or later, then prepare the tools for the mathematical programming languages you use.

Mathematical programming languageInstall
AMPL (.mod)AMPL
MiniZinc (.mzn)MiniZinc with HiGHS (the default) or Gurobi

Configure tool paths (optional)

If a tool is outside your PATH, run source init.sh from the repository root in the terminal you will use for the guide. Use the command for your model format and replace the paths with your own.

# AMPL
source init.sh --ampl /path/to/ampl

# MiniZinc with HiGHS
source init.sh --minizinc /path/to/minizinc --highs /path/to/highs

# MiniZinc with Gurobi (use the Gurobi installation directory)
source init.sh --minizinc /path/to/minizinc --gurobi /path/to/gurobi

Configure your LLM

LLM4MOR supports the OpenAI-compatible Chat Completions and Responses APIs. It uses Chat Completions by default. For instructions on using the Responses API, see the GitHub repository.

Set the API key, base URL, and model name for your LLM provider.

export LLM_API_KEY="your-api-key"
export LLM_BASE_URL="https://your-provider.example/v1"
export LLM_MODEL="your-model-name"

Run the AMPL example

Reformulate the model

Run these commands from the repository root.

cd example
python3 ../llm_analyze.py example.mod --output-dir reformulation

Inspect the reformulation output

Look for these files in example/reformulation/.

example/reformulation/
├── example.llm.mod         # reformulated AMPL model
├── example.llm.map.py      # mapping script for solution verification
├── example.llm.report.md   # reformulation report in Markdown
└── example.llm.report.tex  # reformulation report in LaTeX

Verify the solution against the original model

From the example directory, run the script to verify the solution supplied with the repository.

bash verify.sh

Open output/verification.json to see the result.

Use your own model

From the repository root, choose the command for your model file.

AMPL

python3 llm_analyze.py path/to/model.mod --output-dir outputs/ampl

MiniZinc

python3 llm_analyze.py path/to/model.mzn --output-dir outputs/minizinc

Verify your solution

Solve the reformulated model and save the result in a .sol.json file with variables and objective fields. If your model uses a separate data file, use the same file for solving and verification. Omit --data if your model contains its own data.

AMPL

python3 verify_solution.py path/to/model.mod \
  --sol path/to/model.sol.json \
  --map outputs/ampl/model.llm.map.py \
  --data path/to/instance.dat \
  --output verification.json

MiniZinc

python3 verify_solution.py path/to/model.mzn \
  --sol path/to/model.sol.json \
  --map outputs/minizinc/model.llm.map.py \
  --data path/to/instance.dzn \
  --backend highs \
  --output verification.json

MiniZinc verification uses HiGHS by default. If you configured Gurobi, use --backend gurobi.
